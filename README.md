# Автотесты интернет-магазина «Материк»

Глеб Савченко, группа 411. В проекте 9 сценариев Playwright для интернет-магазина: вход по почте, отрицательные проверки авторизации и путь от поиска товара до формы оформления самовывоза. Сквозной тест останавливается перед подтверждением заказа и восстанавливает исходное количество товара в корзине. [Сайт магазина](https://www.materik-m.ru/)

## Показ на практике

Нужны Windows, Node.js 24 с npm и Microsoft Edge. Команда для PowerShell из папки проекта

```powershell
.\run.cmd --demo
```

Скрипт установит зависимости по `pnpm-lock.yaml`, запустит ТК-А07 в видимом Edge с замедлением действий и откроет свежий отчёт Allure. Тест заполнит форму вымышленной почтой и паролем и проверит, что у поля пароля тип `password`. Данные остаются в форме до закрытия браузера.

1. В терминале покажите строку `Режим: видимый браузер (headed)` и окно Edge с формой авторизации.
2. В выводе теста найдите `Данные входа: login=*** password=***`. В Allure эта строка есть во вложении **After Hooks → Журнал прогона**. Значения маскируются до записи в журнал и вывода в терминал.
3. В Allure откройте **Результаты → materik-ui → login.spec.js → ТК-А07 · Пароль скрыт при вводе**. Разверните шаг «Набрать пример и проверить скрытый режим поля» и откройте PNG **Форма входа с маскировкой**. На снимке закрыты поля ввода. Если окно отчёта закрыто, путь к `runs/<идентификатор>/report/index.html` указан в терминале.
4. В конструкторе `LoginPage` объявлены локаторы, а в ТК-А07 видны вызовы `visit()` и `fillCredentials()`. [LoginPage](ui/login-page.js) · [ТК-А07](autotest/login.spec.js)

## Полный прогон

```powershell
.\run.cmd
```

Введите логин и пароль учебной учётной записи в запросе Windows. Можно передать их в процесс через `MATERIK_LOGIN` и `MATERIK_PASSWORD`. Для сквозного теста нужен доступный товар и отсутствие параллельных действий с корзиной этой учётной записи. Полный прогон также открывает видимый Edge и сохраняет отчёт отдельно от предыдущих запусков. После установки зависимостей команды `pnpm test:demo` и `pnpm test:headed` запускают короткий тест и полный набор соответственно. Без учебных данных полный набор пропустит четыре проверки, которым нужна учётная запись.

## Объект страницы авторизации

`LoginPage` описывает всплывающую форму входа и проверку личного кабинета. `[name=…]` выбирает поля формы по их HTML-именам. `:visible` отбирает видимые элементы. У кнопок телефонной вкладки локаторы используют роль и точное имя.

| Поле `LoginPage` | Локатор | Назначение |
| --- | --- | --- |
| `trigger` | `a.login.show-pvp-auth-block:visible` | Открывает окно авторизации |
| `form` | `#pvp-sms-auth-block .auth-form.active` | Активное окно авторизации, область скриншота |
| `user` | `#loginForm input[name=USER_LOGIN]:visible` | Поле почты |
| `pass` | `#loginForm input[name=USER_PASSWORD]:visible` | Поле пароля |
| `submit` | `#loginForm button[name=Login]:visible` | Отправляет форму входа по почте |
| `phoneTab`, `requestSms` | Кнопки «Телефон» и «Получить код» внутри `form` | Выбор входа по телефону и проверка валидации номера |
| `phone` | `#pvp-sms-auth-phone:visible` | Поле номера телефона |
| `error` | `.login-form-error:visible`, `.phone-auth label.error:visible`, `#pvp-sms-auth-block label.error:visible` | Сообщение об ошибке входа |
| `owner` | `input[name=EMAIL][type=email]` | Почта в личном кабинете для проверки успешного входа |

Объекты сквозного теста описывают поиск, карточку товара, корзину и оформление заказа. [ShopPage](ui/shop-page.js) · [BasketPage](ui/basket-page.js) · [CheckoutPage](ui/checkout-page.js)
